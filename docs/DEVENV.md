- === ONE CORRECTION TO THE DESIGN DOC, FOUND BY TESTING ===  The doc says MySQL's SRID 4326 is latitude-first and would 'silently relocate Kerala into the Indian Ocean'. I tested it on the live 8.0.46 container and that is not true for the code you are actually writing. `ST_Distance_Sphere(POINT(lng,lat), POINT(lng,lat))` returns the identical, correct answer whether the points are SRID 0 or tagged 4326 -- Kochi to Delhi came back as 2079.7 km in both. The `POINT(x,y)` constructor always means x=longitude to ST_Distance_Sphere. The lat-first rule is REAL but it lives in the text functions: `ST_GeomFromText('POINT(a b)', 4326)` parses a as latitude, and `ST_AsText()` on a 4326 geometry PRINTS latitude first -- so a round-trip through WKT, or reading the value in Adminer, silently swaps your coordinates. KEEP the decision (DECIMAL(9,6) columns, SRID 0, POINT(lng,lat)) -- it is correct and I verified Aluva->Kochi as 21.86 km. CHANGE the justification, or an examiner who knows the function will catch you asserting something false. The accurate viva line is: 'I build SRID 0 points from decimal columns so there is no axis-order ambiguity at all; 4326's lat-first axis order only bites you through WKT and GeoJSON, which I never touch.'
